Inside an Iterator Chain, Part 3: Beyond One In, One Out

November 2026

Part 3 of 4 in Inside an Iterator Chain.

Previous: Part 2: Writing a Step | Next: Part 4: Where the & Comes From

Every step in part 2 had the same rhythm: pull one, change it, pass it on. One in, one out. But next promises less than that. It only has to return the next value, or None. How it gets there is up to the step.

This part uses that freedom three ways, then writes the source and the consumer: the step at the centre and the loop that does the asking. The steps from part 2 are still here, and each new step gets a method on the same Steps trait.

1. A step can drop values by looping inside next

To keep only even values, a step pulls until it finds one worth handing on.

impl<I, P> Iterator for Keep<I, P>
where
    I: Iterator<Item = i32>,
    P: FnMut(i32) -> bool,
{
    type Item = i32;

    fn next(&mut self) -> Option<i32> {
        loop {
            let n = self.inner.next()?;
            if (self.test)(n) {
                return Some(n);
            }
        }
    }
}

The loop is the new part. A value that fails the test never leaves this step. The ? still handles the end: if the inner step runs out while we're looking, we're done too.

The struct holds inner and test, and the trait method wraps self as before:

fn keep<P>(self, test: P) -> Keep<Self, P>
where
    Self: Iterator<Item = i32>,
    P: FnMut(i32) -> bool,
{
    Keep { inner: self, test }
}
let out: Vec<i32> = (1..=5).plus(1).times(3).minus(2).keep(|n| n % 2 == 0).collect();
[4, 10, 16]

That's filter. With one difference: the standard library's filter hands its test a reference, not the value. Part 4 explains why.

2. A step can stop before its source runs dry

impl<I: Iterator<Item = i32>> Iterator for First<I> {
    type Item = i32;

    fn next(&mut self) -> Option<i32> {
        if self.left == 0 {
            return None;
        }
        self.left -= 1;
        self.inner.next()
    }
}

Once its count runs out, First says None, however much the inner step has left. It doesn't even ask.

That makes an endless source safe to use:

let out: Vec<i32> = (1..).plus(1).times(3).minus(2).first(3).collect();
[4, 7, 10]

1.. never ends. It doesn't need to. Nothing ever asks it for a fourth value. This is take.

3. A step can remember

A step's struct can hold more than the step before it. This one carries a running total from one call of next to the next.

impl<I: Iterator<Item = i32>> Iterator for Running<I> {
    type Item = i32;

    fn next(&mut self) -> Option<i32> {
        let n = self.inner.next()?;
        self.total += n;
        Some(self.total)
    }
}
let out: Vec<i32> = (1..=5).plus(1).times(3).minus(2).running().collect();
[4, 11, 21, 34, 50]

The standard library's general version of this is scan.

4. The source is a step that holds no step

A range is just an iterator that holds no step, so it has nobody to ask. Its next makes values up. We can write our own.

struct Count {
    at: i32,
    end: i32,
}

impl Iterator for Count {
    type Item = i32;

    fn next(&mut self) -> Option<i32> {
        if self.at > self.end {
            return None;
        }
        let n = self.at;
        self.at += 1;
        Some(n)
    }
}

There's no inner field. That's the only thing that makes it a source rather than a step. With a small count(from, to) function to build one, it drops in where the range was. And since the blanket impl covers every iterator, Count gets plus and the rest for free.

let out: Vec<i32> = count(1, 5).plus(1).times(3).minus(2).collect();
[4, 7, 10, 13, 16]

5. The consumer is a loop that calls next

collect, sum and a for loop all do the same thing. They call next until it says None. Here's ours, as one more method on Steps:

fn total(mut self) -> i32
where
    Self: Iterator<Item = i32>,
{
    let mut sum = 0;
    while let Some(n) = self.next() {
        sum += n;
    }
    sum
}

It returns a number, not another step, so nothing can be chained after it. That's what makes it a consumer: it does the asking, and nothing asks it.

let sum = (1..=5).plus(1).times(3).minus(2).total();
50

A for loop is this same loop with the next calls written for you. collect is this loop pushing each value into a collection.

6. Now a whole chain can be ours

Source, steps and consumer, with nothing from the standard library in the chain:

let sum = count(1, 1_000_000)
    .plus(1)
    .times(3)
    .minus(2)
    .keep(|n| n % 2 == 0)
    .first(3)
    .total();
30

The source could count to a million. It counts to five. first asks keep for three values. To find three even ones, keep has to ask the steps it holds five times. Then first says None, and nothing asks again.

7. Once the shape is clear, impl Iterator can hide the struct

A struct per step is the honest version, and it's how the standard library does it. But once map exists, many new steps are one line long:

trait Steps: Iterator + Sized {
    fn plus(self, amount: i32) -> impl Iterator<Item = i32>
    where
        Self: Iterator<Item = i32>,
    {
        self.map(move |n| n + amount)
    }
}

The struct is still there. It's a Map. The return type just doesn't name it. The trade-off is that nobody else can name it either, which matters if you ever need to store the chain in a struct field.
