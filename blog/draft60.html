Native Neovim for Rust: Docs Under the Cursor

November 2026

When you write iterator chains, you keep needing the same thing: what does this method take, and what does it give back? Neovim can tell you without a plugin or a browser tab. This post collects those habits one at a time, starting with the smallest one.

Everything here is built into Neovim. It assumes rust-analyzer is running as the language server, which is the part that knows about Rust.

Reading key notation

Key names in Vim's notation mix capital and lowercase letters, and the case means different things in different places. Here's how it works:

  • A plain letter's case is literal. K is a capital K, so you press Shift+k. k on its own is just k.
  • Inside a Ctrl combination, case doesn't matter. <C-s>, <C-S> and ^S are all the same key: Ctrl+s, with no Shift. The capital in ^S is only how it's displayed.
  • Shift with Ctrl has to be written out, as <C-S-s>. You'll rarely need it.

This post writes keys lowercase in prose, like Ctrl+s, and adds Shift only when you need to press it.

The trap is reading ^S as "Ctrl+Shift+S". Some terminals, Ghostty among them, report Ctrl+Shift+s as a separate key. When I tried it, nothing was mapped to that key, and it typed ^S into the buffer.

1. Shift+k: docs for the thing under the cursor

Put the cursor on a method name, say find, in normal mode, and press K, which is Shift+k.

self.tasks.iter_mut().find(|t| t.id == id)
//                     ^ cursor here, press Shift+k

A floating window opens with the signature and the docs:

fn find<P>(&mut self, predicate: P) -> Option<Self::Item>
where
    P: FnMut(&Self::Item) -> bool,

That's often all you need. Here, it tells you that the closure gets a reference to each item, and that find hands back an Option, not another iterator.

Press Shift+k a second time to jump into the window. You can then scroll and yank in it like any buffer, and q closes it.

Since Neovim 0.10, K calls vim.lsp.buf.hover() whenever a language server is attached to the buffer. You don't need to map it yourself. Before that, K ran man on the word under the cursor, and it still does in buffers with no language server. See :help K and :help lsp-defaults.

2. Ctrl+s: the signature while you type

Shift+k works in normal mode. When you're partway through typing a call, you want the same information without leaving insert mode.

Type up to the opening parenthesis, and press Ctrl+s (no Shift):

self.tasks.iter_mut().find(
//                          ^ still in insert mode, press Ctrl+s

You get the signature with the argument you're on highlighted, followed by the method's docs. For find that's a good half page.

It works the same way as Shift+k: press Ctrl+s a second time to jump into the window and scroll it, then q to close it and get back to typing.

Neovim 0.11 maps Ctrl+s in insert mode to vim.lsp.buf.signature_help() by default (:help i_CTRL-S). Completion plugins such as blink.cmp often show the same popup automatically as you type, which is handy, but it means you might never find out the key exists. Try it in a config with no plugins to see what's really built in.

3. gx: open a docs link in the browser

Sometimes the float isn't enough, and you want the full page on docs.rust-lang.org. The hover text has links in it, and gx (lowercase g, then x) opens the link under the cursor in your system browser.

There's a catch. The float renders its markdown, and that hides the URL part of each link. If you press gx on what you can see, it gets the visible word, not the address. Here's what I got with the cursor on Some:

vim.ui.open: command failed (4): { "xdg-open", "Some" }

So show the raw markdown first:

  1. Shift+k on the method, and Shift+k again to jump into the float.
  2. Run :set conceallevel=0. The URLs appear.
  3. Put the cursor on a https:// URL and press gx.

Not every link has a URL. Here are two from find's docs, with the markdown showing:

`true`, then `find()` returns [`Some(element)`]. If they all return
`false`, it returns [`None`](https://doc.rust-lang.org/stable/core/option/enum.Option.html#variant.None).

[`None`](https://...) has a full address, so gx opens it. [`Some(element)`] is a rustdoc intra-doc link with nothing after it. rustdoc fills the address in when it builds the web page, but the hover text doesn't include one, so there's nothing for gx to open.

gx calls vim.ui.open(), which runs xdg-open on Linux and open on macOS (:help gx). If you get "command failed", run :messages to see exactly what it was given.
