Inside an Iterator Chain, Part 1: How a Chain Runs

November 2026

Part 1 of 4 in Inside an Iterator Chain.

Previous: none | Next: Part 2: Writing a Step

Most writing about iterators is about syntax: which adapter does what. This series is about shape. Why do map, filter and take snap together in any order? And what would it take to write a step of your own that snaps in just as well?

Part 1 only looks. No new code yet, just a chain we already know, taken apart. The examples were run with rustc 1.97.0, edition 2024.

Here's the job for the whole series. Take the numbers 1 to 5. Add 1, multiply by 3, subtract 2. Then format each one as a two-digit label.

let labels: Vec<String> = (1..=5)
    .map(|n| n + 1)
    .map(|n| n * 3)
    .map(|n| n - 2)
    .map(|n| format!("#{n:02}"))
    .collect();

Output:

["#04", "#07", "#10", "#13", "#16"]

A range, four steps, and collect. Everything in this series is about what happens at those dots.

1. A chain is a recipe, not a run

Building a chain doesn't compute anything. It describes the work. The work happens later, when something asks for values.

let chain = (1..=3).map(|n| {
    println!("adding 1 to {n}");
    n + 1
});
println!("chain built");
let added: Vec<i32> = chain.collect();

Output:

chain built
adding 1 to 1
adding 1 to 2
adding 1 to 3

chain built comes first. Every addition happens inside collect.

2. Each step holds the step before it

Building a chain makes no list. So where does the chain live? In the steps themselves. Each one holds the step before it, and the type says so.

let chain = (1..=3).map(|n| n + 1).map(|n| n * 3).map(|n| n - 2);
println!("{}", std::any::type_name_of_val(&chain));

Output:

core::iter::adapters::map::Map<core::iter::adapters::map::Map<core::iter::adapters::map::Map<core::ops::range::RangeInclusive<i32>, p1c::main::{{closure}}>, p1c::main::{{closure}}>, p1c::main::{{closure}}>

Three Maps, each wrapped around the next. They look alike, so let's name them by their jobs: the plus step, the times step and the minus step. Then the type reads like this:

minus step
  holds the times step
    which holds the plus step
      which holds the range

The step written first is the innermost. The step written last is the outermost. That's the one you hold, and the one collect talks to.

The range, innermost of all, is the source. It holds no step, and no list either. It makes each number when asked.

3. The asking goes in, and the work comes out

collect asks the minus step for a value. The minus step has nothing to work on yet, so it asks the step it holds. The asking goes inward, step by step, to the range.

The range hands out 1. Then the value comes back out, and each step does its job on the way: the plus step adds, the times step multiplies, the minus step subtracts.

let out: Vec<i32> = (1..=3)
    .map(|n| { println!("plus  {n}"); n + 1 })
    .map(|n| { println!("times {n}"); n * 3 })
    .map(|n| { println!("minus {n}"); n - 2 })
    .collect();

Output:

plus  1
times 2
minus 6
plus  2
times 3
minus 9
plus  3
times 4
minus 12

plus prints first. If the work happened on the way in, minus would.

Then collect asks again, and the whole trip repeats for 2, then for 3. The steps don't need to remember anything between trips. Only the range does: it knows which number comes next.

A trip per value sounds like a lot of travel. It isn't. A trip is just functions calling functions, and the compiler usually flattens the whole chain into one plain loop.

4. A step only has to answer one question: what's next?

The asking is a method call, and every step, built-in or not, has the same one. Stripped of its many provided methods, the trait is this:

trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}

Some(value) means "here's one". None means "I'm done". That's the whole contract. Item is the type of value the step hands out.

So the trip in is each step calling next on the step it holds. The trip out is each next returning. You can make the calls by hand, which is all collect does:

let mut chain = (1..=3).map(|n| n + 1).map(|n| n * 3).map(|n| n - 2);
println!("{:?}", chain.next());
println!("{:?}", chain.next());
println!("{:?}", chain.next());
println!("{:?}", chain.next());

Output:

Some(4)
Some(7)
Some(10)
None

Four calls, four trips. On the last one, the range has run out. It answers None, each step passes the None straight back out, and collect knows to stop.

next takes &mut self because a step may change itself when asked. The range does, every time: it moves on to the next number.

What comes next

Every step in a chain holds the step before it and answers next. That's all a step needs to be. Part 2 writes one from nothing, with no map, and gives it a dot so it slots in beside the built-ins. Its next turns out to be two lines: one for the trip in, one for the trip out.
