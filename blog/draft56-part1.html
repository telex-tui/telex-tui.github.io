Inside an Iterator Chain, Part 1: How a Chain Runs

November 2026

Part 1 of 4 in Inside an Iterator Chain.

Previous: none | Next: Part 2: Writing a Step

Most writing about iterators is about syntax: which adapter does what. This series is about shape. Why do map, filter and take snap together in any order? And what would it take to write a step of your own that snaps in just as well?

Part 1 only looks. No new code yet, just a chain we already know, taken apart. The examples were run with rustc 1.97.0, edition 2024.

Here's the job for the whole series. Take the numbers 1 to 5. Add 1, multiply by 3, subtract 2. Then format each one as a two-digit label.

let labels: Vec<String> = (1..=5)
    .map(|n| n + 1)
    .map(|n| n * 3)
    .map(|n| n - 2)
    .map(|n| format!("#{n:02}"))
    .collect();

Output:

["#04", "#07", "#10", "#13", "#16"]

A source, four steps, and collect at the end. Everything in this series is about what happens at those dots.

1. A chain is a recipe, not a run

Building a chain doesn't compute anything. It describes the work. The work happens later, when something asks for values.

let chain = (1..=3).map(|n| {
    println!("adding 1 to {n}");
    n + 1
});
println!("chain built");
let added: Vec<i32> = chain.collect();

Output:

chain built
adding 1 to 1
adding 1 to 2
adding 1 to 3

chain built comes first. Every addition happens inside collect.

2. The last step pulls, one value at a time

collect doesn't wait for the first step to finish its whole range. It asks for one value. The request travels back up the chain to the source, and one value travels down through every step.

let out: Vec<i32> = (1..=3)
    .map(|n| { println!("plus  {n}"); n + 1 })
    .map(|n| { println!("times {n}"); n * 3 })
    .map(|n| { println!("minus {n}"); n - 2 })
    .collect();

Output:

plus  1
times 2
minus 6
plus  2
times 3
minus 9
plus  3
times 4
minus 12

Read it in groups of three. The first value goes all the way through before the second leaves the source. No step ever holds a list.

3. Each step holds the step before it

So if there's no list, where does the chain live? In the steps themselves. Each one wraps the one before it, and the type says so.

let chain = (1..=5).map(|n| n + 1).map(|n| n * 3);
println!("{}", std::any::type_name_of_val(&chain));

Output:

core::iter::adapters::map::Map<core::iter::adapters::map::Map<core::ops::range::RangeInclusive<i32>, p1::main::{{closure}}>, p1::main::{{closure}}>

Strip the paths and the closure names, and the shape is plain:

Map<Map<RangeInclusive<i32>, F1>, F2>

Read it from the inside out. The range is innermost. The first Map holds the range and the first closure. The second Map holds the first Map and the second closure. The outermost step is the one you hold, and it's the one collect asks.

4. A step only has to answer one question: what's next?

Every step, built-in or not, implements the same trait. Stripped of its many provided methods, it's this:

trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}

Some(value) means "here's one". None means "I'm done". That's the whole contract. Item is the type of value the step hands out.

You can call next by hand. It's all collect does, over and over, until it sees None.

let mut chain = (1..=2).map(|n| n + 1).map(|n| n * 3);
println!("{:?}", chain.next());
println!("{:?}", chain.next());
println!("{:?}", chain.next());

Output:

Some(6)
Some(9)
None

Each call to the outer Map makes it call next on the inner Map, which calls next on the range. next takes &mut self because every call moves the step along.

What comes next

Every step in a chain is a value that holds the step before it and answers next. That's all a step needs to be. Part 2 writes one from nothing, with no map, and then gives it a dot so it slots in beside the built-ins.
