Program A: DECLARE positions

Compiles. #![allow(dead_code)] on the first line turns off the warnings for items that main doesn't use; it has no brackets.

#![allow(dead_code)]

fn first<T: Copy>(items: &[T]) -> T {
//      ^^^^^^^^^
//      ①
    items[0]
}

struct Wrapper<T> {
//            ^^^
//            ②
    value: T,
}

enum Either<L, R = L> {
//         ^^^^^^^^^^
//         ③
    Left(L),
    Right(R),
}

union Bits<T: Copy> {
//        ^^^^^^^^^
//        ④
    value: T,
    raw: u64,
}

type Pair<T> = (T, T);
//       ^^^
//       ⑤

trait Processor<T> {
//             ^^^
//             ⑥
    fn process(&self, input: T) -> String;
}

impl<T: Copy> Wrapper<T> {
//  ^^^^^^^^^        ^^^
//  ⑦                ⑧
    fn get(&self) -> T {
        self.value
    }
    fn pair_with<U>(&self, other: U) -> (T, U) {
    //          ^^^
    //          ⑨
        (self.value, other)
    }
}

struct Buf<const N: usize> {
//        ^^^^^^^^^^^^^^^^
//        ⑩
    data: [u8; N],
}

trait Lender {
    type Item<'a> where Self: 'a;
    //       ^^^^
    //       ⑪
    fn lend<'a>(&'a mut self) -> Option<Self::Item<'a>>;
    //     ^^^^                        ^^^^^^^^^^^^^^^^
    //     ⑫                           ⑬
    //                                            ^^^^
    //                                            ⑭
}

fn apply<F>(f: F) -> usize
//      ^^^
//      ⑮
where
    F: for<'a> Fn(&'a str) -> &'a str,
    //    ^^^^
    //    ⑯
{
    f("text").len()
}

fn main() {
    let w = Wrapper { value: first(&[3, 4]) };
    println!("{} {:?} {}", w.get(), w.pair_with('x'), apply(|s| s));
}

Output:

struct Wrapper<T> {

struct Logger;

impl Processor<i32> for Logger {
//            ^^^^^
//            ③
    fn process(&self, input: i32) -> String {
        format!("log {input}")
    }
}

impl<T> From<T> for Wrapper<T> {
//  ^^^     ^^^            ^^^
//  ④       ⑤              ⑥
    fn from(value: T) -> Self {
        Wrapper { value }
    }
}

struct Buf<const N: usize> {
//        ^^^^^^^^^^^^^^^^
//        ⑦
    data: [u8; N],
}

struct Holder<'a> {
//           ^^^^
//           ⑧
    text: &'a str,
}

fn main() {
    let ages: HashMap<String, u8> = HashMap::new();
    //               ^^^^^^^^^^^^
    //               ⑨
    let nested: Vec<Vec<u8>> = Vec::new();
    //             ^^^^^^^^^
    //             ⑩
    //                 ^^^^
    //                 ⑪
    let h: Holder<'static> = Holder { text: "hi" };

    //                 ⑬

    //            ⑮

Program C: other positions

use std::fmt::Display;

fn show_all<I>(items: I) -> String
//         ^^^
//         ①
where
    I: Iterator<Item: Display>,
    //         ^^^^^^^^^^^^^^^
    //         ②
{
    items.map(|x| x.to_string()).collect()
}

fn evens(limit: u32) -> impl Iterator<Item = u32> {
//                                   ^^^^^^^^^^^^
//                                   ③
    (0..limit).filter(|n| n % 2 == 0)
}

fn chars_of<'a>(text: &'a str, _unused: &u8) -> impl Iterator<Item = char> + use<'a> {
//         ^^^^                                              ^^^^^^^^^^^^^      ^^^^
//         ④                                                 ⑤                  ⑥
    text.chars()
}

fn first_item<T: Iterator>(mut it: T) -> Option<<T as Iterator>::Item> {
//           ^^^^^^^^^^^^^                     ^^^^^^^^^^^^^^^^^^^^^^^
//           ⑦                                 ⑧
//                                              ^^^^^^^^^^^^^^^
//                                              ⑨
    it.next()
}

fn greet<S: Into<String>>(name: S) -> String {
//      ^^^^^^^^^^^^^^^^^
//      ⑩
//              ^^^^^^^^
//              ⑪
    name.into()
}

fn main() {
    let empty = <Vec<u8> as Default>::default();
    //          ^^^^^^^^^^^^^^^^^^^^
    //          ⑫
    //              ^^^^
    //              ⑬
    let len = <[i32]>::len(&[1, 2, 3]);
    //        ^^^^^^^
    //        ⑭
    let small = len < 5;
    //              ^
    //              ⑮
    let shifted = len << 1;
    //                ^^
    //                ⑯
    println!("{} {} {}", show_all(evens(5)), empty.len(), greet("ann"));
    println!("{len} {small} {shifted} {:?} {:?}", first_item(chars_of("hi", &0)), first_item(1..3));
    println!("[{:<4}]", "ab");
    //           ^
    //           ⑰
}

How to identify any <: a step-by-step procedure

Work through the questions in order and stop at the first answer that applies. Every example is from programs A, B and C above, which compile; the mark after each example points to it.

Step 1. Is the < inside a string literal or a comment?

  • Yes: it is not Rust syntax. Example: println!("[{:<4}]", "ab") (C⑰), where println! reads :<4 as "left-align in a width of 4".
  • No: go to step 2.

Step 2. Is the token immediately before the < one of impl, for, use or ::?

  • impl: DECLARE for the impl block. Example: impl<T: Copy> Wrapper<T> (A⑦). Scope: to the impl's closing }. Matching fills each name at each use.
  • for: DECLARE (higher-ranked), lifetimes only. Example: F: for<'a> Fn(&'a str) -> &'a str (A⑯). Scope: only that bound or type. The borrow checker fills it at each call.
  • use: precise capturing list. Example: -> impl Iterator<Item = char> + use<'a> (C⑥).
  • ::: SUPPLY (turbofish). Examples: "5".parse::<u8>() (B⑬), Vec::<u8>::with_capacity(2) (B⑭). The list belongs to the name just before the ::.
  • None of these: go to step 3.

Step 3. Is the token immediately before the < a name that is being defined right here, after fn, struct, enum, union, trait or type?

  • Yes: DECLARE. Examples: fn first<T: Copy> (A①), fn pair_with<U> (A⑨), struct Wrapper<T> (A②), enum Either<L, R = L> (A③), union Bits<T: Copy> (A④), trait Processor<T> (A⑥), type Pair<T> (A⑤), type Item<'a> inside a trait (A⑪). Scope: to the end of that item. An entry with =, such as R = L, is a default (item 16).
  • No: go to step 4.

Step 4. Is the < in a type or in an expression?

A type is what follows : in a let, a parameter or a field; what follows ->; an impl header; anything inside another bracket list; what follows dyn, impl or as; and a bound. Everything else in a function body is an expression.

  • In a type, after a name: SUPPLY. Examples: let ages: HashMap<String, u8> (B⑨), impl Processor<i32> for Logger (B③), Box<dyn Processor<i32>> (B⑳), S: Into<String> (C⑪), Self::Item<'a> (A⑭). Go to step 5.
  • In a type, after punctuation such as :, &, (, ,, -> or another <: qualified path. Example: the second < in Option<<T as Iterator>::Item> (C⑨). The << there is two brackets: the first < is a SUPPLY list for Option (C⑧).
  • In an expression, after a value (a name, a literal, ) or ]): an operator. Examples: len < 5 (C⑮), len << 1 (C⑯), (x as usize) < limit (item 18). One exception: right after x as usize, the parser is still reading a type, so x as usize < limit starts a SUPPLY list and fails (item 18). And x<-1 fails because <- is one token; write x < -1.
  • In an expression, after =, (, , or an operator, or at the start of a statement: qualified path. Examples: let empty = <Vec<u8> as Default>::default(); (C⑫), let len = <[i32]>::len(&[1, 2, 3]); (C⑭).

Step 5. Inside the SUPPLY list, how is each entry written?

  • Name = Type: associated type binding. Example: impl Iterator<Item = u32> (C③).
  • Name: Bound: associated type bound. Example: I: Iterator<Item: Display> (C②).
  • Anything else: it fills one parameter of that name's DECLARE list, in order. Example: HashMap<String, u8> (B⑨) fills K with String and V with u8; S, left out at the end, gets its default RandomState (item 16). A const argument that is an expression needs braces: Buf<{ 2 * 3 }> (B⑰).

Step 6. Who chose what is in the SUPPLY list? Look at where it is written.

  • In a let annotation, a field type or a function signature: the author of that line. Example: let ages: HashMap<String, u8> (B⑨).
  • After the trait name in an impl header: the implementor. Example: impl Processor<i32> for Logger (B③).
  • In a turbofish: the caller. Example: "5".parse::<u8>() (B⑬).
  • It contains a name from an enclosing DECLARE list: whoever fills that name. Example: in impl<T> From<T> for Wrapper<T> (B⑤, B⑥), matching fills T; in fn first_item<T: Iterator>(…) -> Option<<T as Iterator>::Item> (C⑧), the caller fills T.
  • No brackets were written at all: inference filled the parameter, or a default did. Examples: first(&[3, 4]) in program A, where inference fills T with i32; let a: Meters = … in item 16, where the default fills T with f64.

Worked example: impl<'a, K: Hash + Eq, V> FromIterator<(&'a K, V)> for MyMap<&'a K, V> where V: Clone

The signature, every bracket and every generic name marked

Excerpt (the impl line of the program in the next part, unchanged):

impl<'a, K: Hash + Eq, V> FromIterator<(&'a K, V)> for MyMap<&'a K, V> where V: Clone {
//  ^^^^^^^^^^^^^^^^^^^^^             ^^^^^^^^^^^^          ^^^^^^^^^^       ^
//  ①                                 ⑤                     ⑨                ⑬
//   ^^  ^             ^                 ^^ ^  ^              ^^ ^  ^
//   ②   ③             ④                 ⑥  ⑦  ⑧              ⑩  ⑪  ⑫
# What is marked Label Arguments What it does
① < immediately after impl DECLARE Declares 'a, K and V for the impl block. Scope: from this < to the impl's closing }, including the where clause and from_iter.
② 'a inside ① declares The lifetime parameter 'a.
③ K inside ① declares The type parameter K, with the bounds Hash and Eq.
④ V inside ① declares The type parameter V. Its bound is added at ⑬.
⑤ < immediately after FromIterator SUPPLY (&'a K, V): built from passed-on 'a, K, V Fills FromIterator's one parameter, A in std's pub trait FromIterator<A>: Sized, with the tuple type (&'a K, V). The impl's author chose it: this impl builds a MyMap from pairs of a borrowed key and a value.
⑥ 'a inside ⑤ uses 'a from ①.
⑦ K inside ⑤ uses K from ①.
⑧ V inside ⑤ uses V from ①.
⑨ < immediately after MyMap SUPPLY &'a K: built from passed-on 'a, K; V: passed on, from impl<'a, K: Hash + Eq, V> Fills the struct's two parameters: the struct's K with &'a K and the struct's V with V. This is the self type (item 4).
⑩ 'a inside ⑨ uses 'a from ①.
⑪ K inside ⑨ uses K from ①, behind a reference.
⑫ V inside ⑨ uses V from ①.
⑬ V after where uses V from ①, with the bound Clone.

The trap in this line: the struct is declared struct MyMap<K, V>, and the impl also has a K and a V, but they are different parameters. At ⑨, the struct's K is filled with &'a K, a reference to the impl's K. So this impl covers only maps whose keys are references, such as MyMap<&String, u8>, and not MyMap<String, u8>.

The whole program

Compiles.

use std::collections::HashMap;
use std::hash::Hash;

struct MyMap<K, V> {
//          ^^^^^^
//          ①
    inner: HashMap<K, V>,
    //            ^^^^^^
    //            ②
}

impl<'a, K: Hash + Eq, V> FromIterator<(&'a K, V)> for MyMap<&'a K, V> where V: Clone {
//  ^^^^^^^^^^^^^^^^^^^^^             ^^^^^^^^^^^^          ^^^^^^^^^^
//  ③                                 ④                     ⑤
    fn from_iter<I: IntoIterator<Item = (&'a K, V)>>(iter: I) -> Self {
    //          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    //          ⑥
    //                          ^^^^^^^^^^^^^^^^^^^
    //                          ⑦
        let mut inner = HashMap::new();
        for (k, v) in iter {
            inner.insert(k, v.clone());
        }
        MyMap { inner }
    }
}

fn main() {
    let names = vec![String::from("ann"), String::from("bob")];
    let map: MyMap<&String, u8> = names.iter().zip([1, 2]).collect();
    //            ^^^^^^^^^^^^^
    //            ⑧
    println!("{} {:?}", map.inner.len(), map.inner.get(&names[1]));
}

③ < immediately after impl DECLARE ① in the excerpt.
④ < immediately after FromIterator SUPPLY (&'a K, V): built from passed-on 'a, K, V ⑤ in the excerpt.
⑤ < immediately after MyMap in the impl header SUPPLY &'a K: built from passed-on 'a, K; V: passed on, from impl<'a, K: Hash + Eq, V> ⑨ in the excerpt.
⑥ < immediately after from_iter DECLARE Declares I with the bound IntoIterator<Item = (&'a K, V)>. Scope: from this < to the closing } of from_iter's body. std declares the same method as fn from_iter<T: IntoIterator<Item = A>>(iter: T) -> Self;, and an impl may rename T to I.
⑦ < immediately after IntoIterator other: associated type binding Requires I's Item to be (&'a K, V), the tuple that ④ supplied.
⑧ < immediately after MyMap in let map: MyMap<&String, u8> SUPPLY &String: concrete; u8: concrete Fills the struct's K with &String and V with u8, chosen by the author of the let map line.

Who fills each name, and when

Everything happens at compile time, at the call names.iter().zip([1, 2]).collect():

  1. collect is declared in std as fn collect<B: FromIterator<Self::Item>>(self) -> B. The annotation at ⑧ fills B with MyMap<&String, u8>. The iterator's Item is (&String, u8): names.iter() yields &String, and [1, 2] yields integers, which inference makes u8 to fit.
  2. So rustc needs impl FromIterator<(&String, u8)> for MyMap<&String, u8>. Matching the header against it: MyMap<&'a K, V> against MyMap<&String, u8> fills K with String, V with u8, and 'a with the borrow of names that names.iter() made. The borrow checker chose that lifetime.
  3. rustc checks the bounds: String: Hash + Eq holds, and u8: Clone holds.
  4. Inference fills from_iter's I with the iterator type Zip<std::slice::Iter<'_, String>, std::array::IntoIter<u8, 2>>, and rustc compiles one copy of from_iter for that K, V and I.

Quiz: ten brackets

For each question, say what the bracket marked ① is (DECLARE, SUPPLY, or which kind of "other"), and who fills or chooses what is in it. Every snippet compiles. The answers are at the end.

impl<T> From<T> for Wrapper<T> {
//          ^^^

    }

Question 10.

fn chars_of<'a>(text: &'a str, _unused: &u8) -> impl Iterator<Item = char> + use<'a> {
//                                                                              ^^^^
//                                                                              ①
    text.chars()
}

fn main() {
    let n = 0_u8;
    println!("{}", chars_of("quiz", &n).count());
}

Answers

  1. SUPPLY. The < immediately after From in an impl header fills From's parameter with T from impl<T>. Matching fills that T: at Wrapper::from(5_u8), with u8. One compiled copy per type used.
  2. SUPPLY (turbofish). The < immediately after :: fills parse's F with u8. The caller chose it, at this call. The program prints 7.
  3. DECLARE. The < immediately after impl declares T for the impl block. Scope: to the impl's closing }. Matching fills it at each use: at Wrapper('q').get(), with char.
  4. Other: qualified path. The token before this < is =, in an expression. It names default from impl Default for Vec<u8>. The author of the let empty line chose both the type and the trait. The < after Vec inside it is a SUPPLY list.
  5. Other: associated type binding. The < immediately after Iterator in a dyn type requires the dyn type's Item to be u8 (items 8 and 12). The author of the let it line chose u8.
  6. DECLARE (higher-ranked). The < immediately after for declares 'a for the one bound Fn(&'a str) -> &'a str. The borrow checker fills 'a at each call f(&local), with a borrow of local, which exists only inside apply (item 10).
  7. SUPPLY. The < immediately after Buf in a type fills the const parameter N with SIZE * 2, which is 4. An expression must be in braces (item 13). The author of the let b line chose it.
  8. Other: qualified path. This is the second < of the << after Option. The first < is Option's SUPPLY list; this one starts <T as Iterator>::Item, which names Iterator's Item for T (items 9 and 18). The caller of first_item fills T: at first_item("ab".chars()), with Chars, so Item is char.
  9. Other: less-than operator. The token before it is ), so the parser is in an expression and reads a comparison. Without the parentheses, len as u8 < max would start a SUPPLY list for u8 and fail (item 18). It prints true because 300_u32 as u8 is 44.
  10. Other: precise capturing list. The < immediately after use lists the generic parameters the hidden return type may use: 'a only, not the lifetime of _unused (item 11). The author of chars_of wrote it.
