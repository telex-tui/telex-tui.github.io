Item 13 — Const generics: <const N: usize>

A const parameter (defined in part 1) is declared with the keyword const inside a DECLARE list, and its generic argument is a value, not a type. Buf<4> and Buf<16> are two different types, and each value gets its own compiled copy of the code that uses it, just as each type does for a type parameter. Who fills it: whoever writes the SUPPLY list, or inference, usually from an array's length.

13.1 Declaring and supplying a const parameter

Compiles.

struct Buf<const N: usize> {
//        ^^^^^^^^^^^^^^^^
//        ①
    data: [u8; N],
}

impl<const N: usize> Buf<N> {
//  ^^^^^^^^^^^^^^^^    ^^^
//  ②                   ③
    fn new() -> Self {
        Buf { data: [0; N] }
    }
    fn capacity(&self) -> usize {
        self.data.len()
    }
}

fn sum<const N: usize>(values: [u32; N]) -> u32 {
//    ^^^^^^^^^^^^^^^^
//    ④
    values.iter().sum()
}

const SIZE: usize = 4;

fn main() {
    let small: Buf<16> = Buf::new();
    //            ^^^^
    //            ⑤
    let sized = Buf::<SIZE>::new();
    //               ^^^^^^
    //               ⑥

    //              ^^^^^^^^^^^^^^
    //              ⑦

}

Item 14 — Generic associated types: type Item<'a>

An associated type (defined in part 1) can have its own DECLARE list, written immediately after its name: type Item<'a>; or type Of<T>;. This is called a generic associated type. Each use then needs a SUPPLY list after the associated type's name, such as Self::Item<'a>. Who fills it: whoever writes that use, usually a method signature in the trait that passes its own parameter along.

14.5 Why not a trait parameter

A generic impl of a trait with a DECLARE list also covers every element type: impl<T> Container<T> for VecFamily. The difference shows in a function that uses one family at two element types.

Item 17 — Places that can't take generic parameters

Only these can have a DECLARE list: functions and methods, structs, enums, unions, type aliases, traits, impl blocks, associated types (item 14), and the for<'a> lists of item 10. Everything else can't. This item covers closures, const and static items in detail, then lists the rest in one table.

② <= immediately after a other: less-than-or-equal operator 3 <= 5 is true. One token, not < then =.
③ << immediately after a other: left shift operator 3 << 2 is 12. One token.
④ <<= immediately after flags other: left shift assignment operator Shifts flags left by 3 and stores the result: 1 becomes 8. One token.
⑤ > immediately after a other: greater-than operator 3 > 5 is false.
⑥ >> immediately after b other: right shift operator 5 >> 1 is 2. One token.
⑦ < immediately after : inside the string "[{:<5}]" other: inside a string literal Not Rust syntax: println! reads it as "left-align in a width of 5".

18.2 How the parser tells them apart

Rule 1: in a type, a < after a name is always a DECLARE or SUPPLY list. Outside { … } (item 13), types have no operators. Write this: let v: Vec<u8> = Vec::new();.

Rule 2: in an expression, a < after a value or a name is less-than (except after as and a type, rule 3). So generic arguments in an expression need ::<, the turbofish (item 7).

Rule 4: rustc first groups characters into tokens (<=, <<, <<=, >>, >= and <- are each one token), and inside DECLARE and SUPPLY lists the parser splits <<, >> and >= again as needed.
