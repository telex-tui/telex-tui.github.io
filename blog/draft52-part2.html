Item 6 — Generic arguments in type position: Vec<i32>, HashMap<String, u8>, &'a str

Wherever the grammar expects a type, a < immediately after a type's name is always a SUPPLY list, and no :: is needed. The type positions are let annotations, function parameter and return types, field types, impl headers, and the inside of another SUPPLY list.

6.1 SUPPLY lists in type positions, nested

6.2 Lifetime arguments

Compiles.

use std::borrow::Cow;

struct Excerpt<'a> {
//            ^^^^
//            ①
    text: &'a str,
}

fn first<'a>(e: &Excerpt<'a>) -> &'a str {
//      ^^^^            ^^^^
//      ②               ③
    e.text.split(' ').next().unwrap_or("")
}

fn label(n: u8) -> Cow<'static, str> {
//                    ^^^^^^^^^^^^^^
//                    ④
    if n == 0 { Cow::Borrowed("none") } else { Cow::Owned(n.to_string()) }

fn main() {
    let book = String::from("angle brackets");

    //            ⑤
    let fixed: Excerpt<'static> = Excerpt { text: "static text" };
    //                ^^^^^^^^^
    //                ⑥
    println!("{} {} {} {}", first(&e), first(&fixed), label(0), label(7));
}

6.5 Which lifetime parameters a turbofish can supply

Item 1.4 showed longer::<'static>(…) failing with E0794. Two terms explain it:

  • A late-bound lifetime parameter appears in the function parameter list and in no bound or where clause. 'a in fn longer<'a>(x: &'a str, y: &'a str) -> &'a str is late-bound. rustc treats it as part of the function's signature, chosen anew by the borrow checker at every call, so there is nothing to supply at the path.
  • An early-bound lifetime parameter is any other. 'a in fn pick<'a, T>(x: &'a T) -> &'a T where T: 'a is early-bound, because the where clause mentions it. rustc treats it like a type parameter of the function, so a turbofish can supply it:

Compiles.

fn pick<'a, T>(x: &'a T) -> &'a T
//     ^^^^^^^
//     ①
where
    T: 'a,
{
    x
}

static FIVE: u8 = 5;

fn main() {
    let r = pick::<'static, u8>(&FIVE);
    //            ^^^^^^^^^^^^^
    //            ②
    println!("{r}");
}

Output:

5
# Position Label Arguments What it does
① < immediately after pick DECLARE Declares 'a (early-bound, because of T: 'a) and T. Scope: from this < to the closing } of pick's body.
② < immediately after :: in pick::<'static, u8> SUPPLY 'static: concrete; u8: concrete Fills 'a with 'static and T with u8. The caller chose both, lifetime first.

6.6 Lifetimes left out of an impl header

Compiles.

struct Name(String);

impl From<&str> for Name {
//       ^^^^^^
//       ①
    fn from(s: &str) -> Name {
        Name(s.to_uppercase())
    }
}

impl<'a> From<&'a [u8]> for Name {
//  ^^^^     ^^^^^^^^^^
//  ②        ③
    fn from(bytes: &'a [u8]) -> Name {
        Name(String::from_utf8_lossy(bytes).into_owned())
    }
}

fn main() {
    let owned = String::from("ada");
    let a = Name::from(owned.as_str());
    let b = Name::from(&b"bob"[..]);
    println!("{} {}", a.0, b.0);
}

Output:

ADA bob
# Position Label Arguments What it does
① < immediately after From in impl From<&str> for Name SUPPLY &str: concrete Fills From's T with &str, whose lifetime is left out. In an impl header, each left-out lifetime becomes a lifetime parameter of the impl.
② < immediately after impl in impl<'a> From<&'a [u8]> for Name DECLARE Declares 'a for this impl. Scope: from this < to the impl block's closing }.
③ < immediately after From in the same header SUPPLY &'a [u8]: built from passed-on 'a Fills From's T with &'a [u8].

The two headers have the same shape: impl From<&str> for Name behaves like impl<'x> From<&'x str> for Name with a lifetime nobody named. That is why Name::from(owned.as_str()) works with a borrow of a local String, not only with 'static strings. std's impl From<&str> for String (item 4.4) is written the same way.

Item 7 — Generic arguments in expression position: the turbofish

Inside an expression, a SUPPLY list must be written ::<…>, because a bare < after a name is read as "less than". The SUPPLY list fills the generic parameters of the path segment immediately before the ::.

The parser decides what < means as it reads, before it knows what Vec is. In an expression, a name followed by < could be a comparison such as a < b, so < alone means less-than. ::< can never start a comparison, so it marks a SUPPLY list without guessing.

Item 8 — Associated type bindings: Iterator<Item = u8>

Inside the SUPPLY list after a trait's name, Name = Type fills no generic parameter. It pins one of the trait's associated types, which the trait's implementor already decided, and so it is a requirement, not a choice. I label it "other: associated type binding".

8.1 The three places it appears

Compiles.

fn sum_bytes<I: Iterator<Item = u8>>(it: I) -> u32 {
//          ^^^^^^^^^^^^^^^^^^^^^^^^
//          ①
//                      ^^^^^^^^^^^
//                      ②
    it.map(u32::from).sum()
}

fn words(text: &str) -> impl Iterator<Item = String> {
//                                   ^^^^^^^^^^^^^^^
//                                   ③
    text.split(' ').map(String::from)
}

Item 9 — Qualified paths: <Vec<u8> as Default>::default(), <T as Iterator>::Item

Item 11 — impl Trait in argument and return position

impl Trait writes no DECLARE list, but it still stands for a generic parameter. In argument position it is an anonymous type parameter that the caller fills, like <I: Iterator<Item = u8>>. In return position it is a hidden concrete type that the function's author fills, through the body, and the caller never learns its name. The only angle brackets involved are SUPPLY lists and bindings inside the bound, plus, in return position, an optional use<…> list.

Item 12 — dyn Trait<…>: generic arguments on trait objects

A dyn type names a trait with all of its generic parameters and associated types filled, because one compiled table of function pointers must serve every value behind it. So the SUPPLY list after the trait's name is required, and so are bindings for its associated types. A method with its own DECLARE list can't go in such a table, which is why it blocks dyn (item 5.6).
